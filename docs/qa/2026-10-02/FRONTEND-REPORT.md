# Frontend replacement pass — package and framework consumers

PR: opened by orchestrator
CI status: pending at time of writing

This SDK has no UI, dev server or browser-delivered product. Package installation, public TypeScript declarations, framework tool protocols and execution safety replace frontend/browser QA. Browser rendering, Chromium/Firefox/WebKit, Lighthouse, axe and screenshots are not applicable. All execution used synthetic arguments, client doubles and local tool counters; no model/provider/API calls were made.

## Results

Four findings in this pass: **Critical=1, High=1, Medium=2, Low=0**. The coordinator separately records development-dependency audit results; they are not included in these four findings.

- `frontend-adapters.test.mjs`: 30 tests, 21 pass, 9 expected failures/TODO, exit 0. It covers all four adapters, success, rejection, timeout, transport failure, argument/option forwarding, tool naming, LangChain allow/deny lists, Mastra binding and strict consumers.
- `frontend-langchain.integration.test.mjs` against real `@langchain/core@1.2.14`: 8 tests, 3 pass, 5 expected failures/TODO, exit 0. Without the optional framework package the eight tests explicitly skip; the committed artifact proves the real integration was run separately.
- Real `ai@7.0.127` and `@openai/agents@0.18.0` factories: both JS wrappers execute once on approval and execute zero times on rejection. Real TypeScript tool types fail compilation (FE-002), while the strict consumer using compatible broad callback parameters compiles.
- A clean source package contains only three files and fails to import. A local Git dependency installation reproduces the same failure (FE-004), so this is not merely an inference from the scripts.
- Build, project typecheck, built-package verification, minimum supported Node and dependency audit are coordinated centrally and cited in the consolidated report. Core safety issues shared by adapters are recorded in Backend findings rather than counted twice.

## Evidence and execution notes

All shell commands, exits and UTC times are retained in [FRONTEND-LOG.md](FRONTEND-LOG.md) and `artifacts/frontend-commands.jsonl`. New defect tests use TODO finding IDs, leaving the product unchanged and the test exit code green. The bare compiler/import reproductions deliberately returned nonzero and remain visible in the log.

The first direct local Git install encountered a partial-clone history limitation: npm's mirror clone could not obtain an older promisor object. That attempt is [recorded](artifacts/frontend-local-git-consumer.txt), not treated as a product failure. A shallow clone of the available current tree then succeeded and enabled the exact installation reproduction. Only local `file://` Git sources were supplied; the failed mirror clone reported lazy fetching disabled, but implicit promisor-fetch network activity was not independently traced.

The npm tarball install used `--ignore-scripts` only after the clean-source pack already established the missing runtime files; the decisive local Git installation did **not** disable lifecycle scripts.

The retained optional LangChain integration accepts a package directory via `SENTINEL_QA_LANGCHAIN_ROOT`; it contains no hardcoded host path. This is a non-secret test path. `run.py` clears service environment variables, then the logged `env ...` command adds only this explicit path. All framework packages came from the public package registry, with versions in [the version artifact](artifacts/frontend-actual-framework-versions.txt).

## Limits

No complete LLM agent/model round trip or live Sentinel delivery channel was exercised. LangChain 1.2.14, AI SDK 7.0.127 and OpenAI Agents 0.18.0 were the real framework versions tested. Older peer versions and a real Mastra package remain unverified; Mastra coverage is structural. This pass establishes local package/tool behavior, not server permissions, service availability, published npm availability or deployment status. No browser assets exist to screenshot.

## Final runner compatibility note

Known-defect assertions execute as TODOs on Node 20+ and were verified failing for the intended reasons on Node 24/26. Node 18.17 treats failing TODOs as a nonzero process exit even with `fail 0`; `tests/qa/known-defect.mjs` therefore marks those cases explicitly skipped on Node 18, with their finding IDs. Passing controls still execute. This is a QA harness adjustment, not a product fix. See the consolidated runtime matrix in COVERAGE.md.
